ПОЯСНЕНИЕ К ЛАБОРАТОРНЫМ РАБОТАМ № 2 И № 3
Приложение Task Tracker

Этот документ объясняет устройство учебного приложения простыми словами. Его можно читать, даже если вы раньше не программировали.

ВАЖНО О ТОМ, ЧТО ИМЕННО ОПИСАНО

Ниже описано, как приложение устроено сейчас. Это не точный список файлов, которые менялись при разработке: в папке проекта нет доступной истории Git, позволяющей надёжно сравнить изменения. Документ объясняет файлы, в которых реализованы функции ЛР 2 и ЛР 3.

1. ЧТО ДЕЛАЕТ ПРИЛОЖЕНИЕ

Task Tracker — небольшой список задач. Пользователь может:
- посмотреть список задач;
- отфильтровать его по статусу;
- открыть подробности задачи;
- создать задачу;
- изменить задачу;
- удалить задачу после подтверждения.

Данные сохраняются только в памяти открытого приложения. После перезагрузки страницы снова загружаются демонстрационные задачи. В этой версии нет базы данных и постоянного сохранения в браузере.

2. НЕСКОЛЬКО ОСНОВНЫХ ПОНЯТИЙ

React — библиотека JavaScript для построения интерфейсов.

Компонент — отдельная часть интерфейса. Обычно это функция, которая возвращает разметку. Например, TasksPage показывает страницу со списком, а TaskCard показывает одну карточку задачи.

JSX — разметка, похожая на HTML, которую можно писать внутри JavaScript/TypeScript-кода React. Запись <h1>Задачи</h1> создаёт заголовок.

TypeScript — JavaScript с проверкой типов. Типы помогают заранее увидеть, например, что в статус нельзя случайно записать произвольное значение.

Маршрут (route) — правило, связывающее адрес страницы с нужным компонентом. Например, адрес /tasks показывает список задач.

Props (свойства) — данные и функции, которые родительский компонент передаёт дочернему. Например, App передаёт список tasks в TasksPage.

Состояние (state) — данные, за которыми следит React. Когда состояние меняется, React обновляет интерфейс.

Хук (hook) — специальная функция React. Например, useState хранит состояние, а useNavigate позволяет перейти на другой адрес программно.

Массив — упорядоченный список значений. Здесь массив tasks содержит несколько объектов задач.

Объект — набор связанных полей и значений. Одна задача — объект с названием, сроком, статусом и другими свойствами.

Идентификатор (id) — уникальное значение, по которому можно отличить одну задачу от другой.

Иммутабельное обновление — изменение данных без порчи старого массива или объекта. Вместо этого создаётся новый массив или объект. React проще определить такое изменение и обновить экран.

3. ЛАБОРАТОРНАЯ РАБОТА № 2: СТРАНИЦЫ И НАВИГАЦИЯ

Цель этой части — разделить приложение на страницы и сделать переходы между ними по адресам браузера.

Адреса приложения:
- / — перенаправляет на список задач;
- /tasks — список задач;
- /tasks/new — форма создания;
- /tasks/t1 — подробности задачи с идентификатором t1;
- /tasks/t1/edit — редактирование задачи t1;
- любой неизвестный адрес — страница «Страница не найдена».

Символ : в маршруте, например /tasks/:id, означает переменную часть адреса. Если браузер открыт по адресу /tasks/t1, значение id будет равно t1.

3.1. frontend/src/main.tsx — запуск приложения

Этот файл подключает приложение к странице браузера.

StrictMode — специальный режим React для разработки, который помогает заметить некоторые проблемы.

createRoot — создаёт корень React в HTML-элементе страницы.

document.getElementById('root') — ищет в HTML элемент с идентификатором root. Внутри него будет показано приложение.

BrowserRouter — включает маршрутизацию по адресной строке браузера.

App — главный компонент приложения, помещённый внутрь BrowserRouter.

3.2. frontend/src/App.tsx — главный компонент и маршруты

App — главный компонент. Он хранит общий список задач, задаёт операции над ним и описывает, какая страница показывается для каждого URL.

useState — хук React для хранения состояния.

tasks — переменная с текущим массивом задач.

setTasks — функция, которой обновляют tasks. Обновление через неё сообщает React, что данные изменились и интерфейс нужно перерисовать.

initialTasks — демонстрационный набор задач, импортированный из файла data/tasks.ts. При первом запуске он копируется в состояние приложения.

Task[] — тип «массив объектов Task». Квадратные скобки [] после типа означают массив.

createTask(draft) — функция создания задачи.
- draft — черновые поля новой задачи, пришедшие из формы.
- crypto.randomUUID() создаёт уникальный идентификатор.
- id — идентификатор только что созданной задачи.
- current — прежнее значение списка tasks на момент обновления.
- [...current, { ...draft, id }] создаёт новый массив: копирует прежние задачи и добавляет новую.
- return id возвращает идентификатор странице создания, чтобы она могла открыть новую задачу.

Три точки ... называются оператором spread. В массиве [...current] они копируют элементы массива. В объекте { ...draft } они копируют поля объекта.

updateTask(id, draft) — функция обновления задачи.
- map перебирает элементы массива и возвращает новый массив той же длины.
- task — одна задача, обрабатываемая в текущем проходе.
- task.id === id проверяет, относится ли задача к нужному идентификатору.
- Если идентификаторы совпали, создаётся объект с новыми полями черновика и прежним id.
- Если не совпали, задача остаётся без изменений.

deleteTask(id) — функция удаления задачи.
- filter перебирает массив и оставляет только элементы, для которых условие истинно.
- task.id !== id означает «идентификатор этой задачи не равен удаляемому». Поэтому задача с этим id исключается из нового массива.

Routes и Route — компоненты React Router для описания маршрутов.

path — адрес или шаблон адреса.

element — компонент, который нужно показать при совпадении с маршрутом.

Navigate — компонент перенаправления. В приложении адрес / перенаправляется на /tasks.

replace — свойство перенаправления: заменяет текущую запись истории браузера, а не добавляет ещё одну.

AppLayout — общий каркас страниц.

TasksPage, NewTaskPage, TaskDetailsPage, EditTaskPage и NotFoundPage — компоненты отдельных страниц.

3.3. frontend/src/app/AppLayout.tsx — общий каркас страниц

AppLayout содержит верхнюю часть приложения: название, меню и пояснение о временном хранении данных.

NavLink — ссылка React Router для навигации. Она также умеет показывать, какая ссылка соответствует текущей странице.

Outlet — место, куда Router вставляет выбранную страницу.

aria-label — доступное текстовое название блока навигации, полезное для программ чтения с экрана.

3.4. frontend/src/pages/TasksPage.tsx — страница списка

TasksPage — компонент страницы «Мои задачи».

TasksPageProps — описание свойств, которые принимает компонент.

tasks — список задач, полученный от App через props.

status — выбранное значение фильтра. Значение all означает «показывать все».

setStatus — функция изменения выбранного фильтра.

visibleTasks — новый массив задач, прошедших фильтр.

tasks.filter(...) оставляет задачи, если фильтр равен all или статус задачи совпадает с выбранным статусом.

event — объект события браузера. Он появляется, например, когда пользователь выбирает другой пункт в списке.

event.target.value — выбранное значение поля.

Условие value === 'all' || value === 'todo' || ... проверяет, что в состояние записывается только одно из разрешённых значений фильтра.

visibleTasks.map(...) создаёт карточку TaskCard для каждой видимой задачи.

key={task.id} — уникальный ключ для React. Он помогает React правильно сопоставлять карточки с задачами при обновлении списка.

В интерфейсе различаются две ситуации: если tasks пуст, показывается «Задач пока нет»; если задачи есть, но фильтр не нашёл подходящих, показывается «Подходящих задач не найдено».

3.5. frontend/src/components/TaskCard.tsx — одна карточка

TaskCard — компонент одной карточки задачи.

TaskCardProps — тип его входных свойств.

task — объект задачи, который карточка должна показать.

task.title, task.description, task.dueDate и другие обращения читают значения из полей объекта task.

Link — ссылка React Router. Она открывает подробности задачи.

Шаблон /tasks/${task.id} — строка, в которую подставляется идентификатор. Например, если id равен t1, получится /tasks/t1.

statusLabels — словарь перевода внутреннего статуса на русский текст. Например, todo показывается как «К выполнению».

priorityLabels — словарь перевода внутреннего приоритета на русский текст. Например, high показывается как «Высокий».

Record<Task['status'], string> — тип TypeScript: объект должен иметь подпись для каждого допустимого статуса задачи.

3.6. frontend/src/pages/TaskDetailsPage.tsx — подробности задачи

useParams() читает параметры из URL.

id — параметр идентификатора из адреса, например t1 из /tasks/t1.

useNavigate() возвращает функцию для перехода на другой адрес из кода.

navigate('/tasks') — переход к списку задач.

task — задача, которую find нашёл по id.

find(...) ищет первый элемент массива, подходящий под условие.

if (!task) проверяет, что задача не найдена. В этом случае показывается сообщение «Задача не найдена».

id ?? 'неизвестный' означает: использовать id, если он существует, иначе показать слово «неизвестный». Оператор ?? подставляет значение справа только при отсутствии значения слева.

onDelete — функция удаления, полученная через props от App.

window.confirm(...) показывает стандартное окно подтверждения браузера. Удаление выполняется только если пользователь подтвердил действие.

onDelete(task.id) вызывает удаление именно выбранной задачи.

navigate('/tasks', { replace: true }) возвращает пользователя к списку и заменяет текущий адрес в истории браузера.

3.7. frontend/src/pages/NotFoundPage.tsx — неизвестный адрес

NotFoundPage — простая страница для URL, которому не соответствует известный маршрут.

4. ЛАБОРАТОРНАЯ РАБОТА № 3: ФОРМЫ И ЛОКАЛЬНОЕ СОСТОЯНИЕ

Цель этой части — добавить изменение данных: создание, редактирование, удаление и фильтрацию. Общий список хранится в одном месте — в App. Форма сначала меняет свой отдельный черновик, а сохранение передаёт данные в App.

4.1. frontend/src/components/TaskForm.tsx — форма

TaskForm — общая форма для создания и редактирования задачи.

TaskFormProps — тип входных свойств формы.

initialValues — исходные значения полей. Для создания это пустые значения и настройки по умолчанию; для редактирования — текущие значения задачи.

onSave — функция родительской страницы, которая будет вызвана после проверки формы.

onCancel — функция отмены, заданная родительской страницей.

draft — локальный черновик формы. Пока пользователь вводит данные, меняется именно draft, а не общий список задач.

setDraft — функция обновления draft.

error — строка с сообщением об ошибке. Пустая строка означает, что ошибки нет.

setError — функция установки или очистки сообщения об ошибке.

updateField(field, value) — функция изменения одного поля черновика.

K extends keyof TaskDraft — правило TypeScript: field должен быть названием реально существующего поля TaskDraft. Это предотвращает опечатки в названиях полей.

current — предыдущее значение draft при обновлении.

FormEvent<HTMLFormElement> — тип события отправки HTML-формы.

event.preventDefault() запрещает браузеру отправить форму обычным способом и перезагрузить страницу. Вместо этого данные обрабатывает функция React.

trim() удаляет пробелы в начале и конце текста.

trimmedTitle, trimmedDescription, trimmedTag, trimmedProject и trimmedOwner — очищенные от внешних пробелов значения соответствующих полей.

Проверки перед сохранением:
- название должно содержать от 3 до 100 символов;
- срок должен быть заполнен;
- описание должно быть заполнено;
- если статус задачи done, описание должно содержать не меньше 10 символов.

setError('...') показывает сообщение и прекращает сохранение до тех пор, пока пользователь не исправит значение.

setError('') очищает сообщение, когда проверки пройдены.

onSave({...}) передаёт родительской странице копию данных черновика.

project || 'Task Tracker' означает: если project пустой, использовать Task Tracker.

owner || 'Петренко А.К.' означает: если ответственный не указан, использовать заданное имя по умолчанию.

required — HTML-атрибут, обозначающий обязательное поле. В форме есть noValidate, поэтому правила проверяются написанным кодом, чтобы показывать собственные сообщения.

onChange — обработчик изменения значения поля.

select — выпадающий список, из которого выбирают статус или приоритет.

Проверки в обработчиках статуса и приоритета разрешают только заранее заданные варианты. Это помогает не записать случайное значение в типизированные данные.

role="alert" сообщает вспомогательным технологиям, что появившееся сообщение об ошибке важно.

type="submit" означает, что кнопка отправляет форму.

type="button" означает обычную кнопку, которая сама по себе форму не отправляет. Кнопка «Отмена» имеет именно такой тип.

4.2. frontend/src/pages/NewTaskPage.tsx — создание

NewTaskPage — страница создания задачи.

emptyTask — объект с начальными значениями формы: пустым названием и описанием, статусом todo и значениями по умолчанию для некоторых полей.

handleSave(draft) — вызывается, когда форма успешно проверена и сохранена.

onCreate(draft) — функция из App, которая добавляет задачу и возвращает её id.

navigate(`/tasks/${id}`) после создания открывает страницу новой задачи.

onCancel={() => navigate('/tasks')} задаёт действие для отмены: вернуться к списку.

4.3. frontend/src/pages/EditTaskPage.tsx — редактирование

EditTaskPage — страница редактирования существующей задачи.

tasks — общий список, полученный через props.

onUpdate — функция обновления, переданная из App.

id — идентификатор задачи из URL.

task — найденная задача.

initialValues — копия полей выбранной задачи, переданная в форму. id здесь не нужен, потому что форма редактирует только поля, а идентификатор уже известен странице.

key={task.id} помогает React сбросить локальное состояние формы, если компонент используется для другой задачи.

onSave вызывает onUpdate и возвращает пользователя на подробную страницу задачи.

Если задача с указанным id не найдена, страница сообщает об этом и предлагает вернуться к списку.

5. ТИПЫ И ДЕМОНСТРАЦИОННЫЕ ЗАДАЧИ

5.1. frontend/src/types/task.ts — описание данных

TaskStatus — допустимый тип статуса: todo, in_progress или done.

TaskPriority — допустимый тип приоритета: low, medium или high.

Task — тип полной задачи. В нём описаны поля:
- id — уникальный идентификатор;
- title — название;
- description — описание;
- status — статус;
- dueDate — дата выполнения в виде строки;
- priority — приоритет;
- tag — тег или категория;
- project — проект;
- owner — ответственный.

TaskDraft = Omit<Task, 'id'> — тип черновика. Omit берёт поля типа Task, кроме id. Идентификатор присваивается приложением во время создания задачи.

5.2. frontend/src/data/tasks.ts — начальные данные

tasks — массив демонстрационных объектов типа Task.

t1, t2 и другие значения id — идентификаторы примеров задач.

У каждой задачи должны быть все поля, объявленные в типе Task.

6. КАК ДАННЫЕ ПРОХОДЯТ ЧЕРЕЗ ПРИЛОЖЕНИЕ

Создание:
1. Пользователь открывает /tasks/new.
2. NewTaskPage показывает TaskForm с начальными значениями.
3. Ввод меняет локальный draft внутри TaskForm.
4. При нажатии «Сохранить» форма проверяет поля.
5. TaskForm вызывает onSave.
6. NewTaskPage вызывает onCreate из App.
7. App создаёт id и добавляет задачу в общий tasks.
8. Пользователь переходит на страницу созданной задачи.

Редактирование:
1. Пользователь открывает /tasks/:id/edit.
2. EditTaskPage находит задачу в общем списке.
3. Поля задачи копируются в initialValues формы.
4. Изменения остаются в draft до сохранения.
5. После проверки onUpdate заменяет задачу в общем списке новым объектом.
6. При отмене draft отбрасывается, список не меняется.

Удаление:
1. На странице задачи нажимают «Удалить».
2. Браузер просит подтвердить действие.
3. Если пользователь подтверждает, App удаляет задачу из массива.
4. Приложение возвращает пользователя к списку.

Фильтрация:
1. Пользователь выбирает статус на странице /tasks.
2. Меняется локальное состояние status страницы TasksPage.
3. visibleTasks пересчитывается из tasks.
4. Список показывает только совпавшие задачи. Сам общий массив при этом не меняется.

- .page-section — общий вид секции страницы;
- .section-header — заголовок и действие в шапке списка;
- .filter-panel — панель фильтра;
- .task-list — список карточек;
- .task-card — карточка задачи;
- .task-card__meta — область статуса и тега;
- .task-card__status--todo, .task-card__status--in_progress, .task-card__status--done — стили разных статусов;
- .task-card__details — срок, приоритет и другие подробности;
- .task-form — форма;
- .task-form__grid — группа полей в сетке;
- .task-form__actions — кнопки формы;
- .form-error — сообщение об ошибке;
- .task-actions — действия на странице задачи.

display: flex располагает элементы гибко в строку или колонку.

display: grid располагает элементы в сетку.

gap задаёт промежуток между элементами.

padding — внутренний отступ элемента.

margin — внешний отступ вокруг элемента.

color задаёт цвет текста; background задаёт фон.

border задаёт рамку; border-radius скругляет углы.

:hover — состояние, когда указатель мыши находится над элементом.

:focus-visible — видимое выделение элемента, например при перемещении клавишей Tab.

@media задаёт адаптивные стили для разных размеров окна. В этом проекте правила меняют расположение элементов на широком и узком экране.

box-sizing: border-box включает рамку и внутренние отступы в ширину и высоту элемента.

8. КОРОТКИЙ СЛОВАРЬ КОДА

function — объявляет функцию, то есть именованный блок действий.

const — объявляет переменную, которой нельзя присвоить новое значение. Содержимое объекта или массива при этом не становится автоматически неизменяемым.

return — возвращает результат из функции.

if — выполняет код только при выполнении условия.

=== — сравнивает значения с учётом типа.

!== — проверяет, что значения не равны.

|| — логическое «или».

&& — логическое «и».

! — логическое отрицание; например, !task означает, что task отсутствует или имеет ложное значение.

{ } в JSX позволяют вставлять выражения JavaScript внутрь разметки, например <h1>{task.title}</h1>.

${...} внутри обратных кавычек подставляет значение в строку. Пример: `/tasks/${id}`.

import — подключает код или данные из другого файла либо библиотеки.

export — делает функцию, тип или значение доступным для импорта из других файлов.

type — объявляет тип TypeScript.

as const — говорит TypeScript воспринимать значения объекта как точные постоянные значения, а не как произвольные изменяемые строки.

9. ОГРАНИЧЕНИЯ ТЕКУЩЕЙ ВЕРСИИ

- Данные хранятся только в памяти приложения.
- После обновления страницы задачи создаются заново из демонстрационного набора.
- Сервер, база данных, Supabase и localStorage здесь не используются.
- Удаление доступно с подтверждением браузера.
- Валидация выполняется в TaskForm перед передачей данных в общий список.

10. ГЛАВНОЕ, ЧТО НУЖНО ЗАПОМНИТЬ

App — единое место, где хранится общий список задач.

Страницы получают нужные данные и функции через props.

TaskForm хранит временный черновик, пока пользователь не нажал «Сохранить».

Маршруты определяют, какая страница открывается по адресу браузера.

При добавлении, редактировании и удалении создаётся новый массив, а не изменяется старый напрямую.

Типы Task и TaskDraft описывают, какие данные являются полноценной задачей и какие данные форма может отправить для сохранения.
