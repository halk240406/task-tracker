# Трекер задач (Task Tracker)

Учебное приложение для курса «Практический курс веб-разработки: React, TypeScript, Node и Supabase».

Петренко Александр Кириллович 24ИС

## Тема и сценарий
Task Tracker помогает студенту вести личные задачи. Пользователь добавляет задачу, указывает срок и приоритет, меняет статус, фильтрует список и работает с карточками.

## Стек
React, TypeScript, Vite, React Router

## Версия Node
26.10.0

## Запуск
Из корня скачанного проекта:
```bash
cd frontend
npm ci
npm run dev
```

## Проверка сборки
Остановите dev через Ctrl+C. Выполните в frontend:
```bash
npm run build
npm run preview
```

## Что работает сейчас
- список задач и карточки по маршрутам
- создание, редактирование и удаление записей в локальном состоянии
- фильтр по статусу
- отдельный экран для пустого/неизвестного адреса

## Лабораторная работа 2. Страницы приложения и навигация
Вторая лабораторная посвящена организационной структуре интерфейса приложения:
- настроен маршрутизатор React Router и общий layout страницы;
- добавлены страницы списка задач, карточки задачи, создания задачи и страницы 404;
- при открытии корневого адреса `/` выполняется редирект на `/tasks`;
- каждая задача хранится как отдельный объект в типизированном массиве `Task[]`;
- данные передаются в компоненты через props, а не напрямую через глобальное состояние;
- карточки задач формируются из массива через `map`, с использованием `key={task.id}`.

Пояснение к реализации: список и карточка работают по URL, поэтому ссылка на запись и прямое открытие страницы корректно отображают нужную задачу. Для неизвестного адреса и для отсутствующей записи предусмотрены отдельные сообщения.

## Лабораторная работа 3. Формы и локальное состояние
Третья лабораторная добавляет взаимодействие с данными и проверку ввода:
- список задач теперь хранится в локальном состоянии компонента `App` через `useState`;
- добавлена переиспользуемая форма `TaskForm`, которая используется и для создания, и для редактирования;
- реализованы `createTask`, `updateTask` и `deleteTask` без мутаций исходного массива;
- форма работает через отдельный черновик `draft`, поэтому отмена не изменяет сохранённые данные;
- добавлена валидация: обязательное поле срока, обязательное название, проверка длины и правило для завершённой задачи;
- добавлен фильтр по статусу: «Все задачи», «Запланировано», «В работе», «Готово»;
- при удалении показывается подтверждение через `window.confirm`.

Такой подход соответствует задаче: общий список хранится в одном месте, а страницы получают только нужные данные и колбэки. Это делает приложение предсказуемым и устраняет проблему, когда разные страницы работают с разными копиями массива.

## Ограничения
Данные хранятся только в памяти открытого приложения. После обновления страницы список восстанавливается из демонстрационного набора. Очередные лабораторные добавят HTTP/Supabase и хранение на сервере.

## Ответы на возможные вопросы преподавателя

### 1. Почему данные живут в памяти, а не в localStorage?
Поскольку по условию лабораторной работы данные должны быть временными, а серверный слой и интеграция с Supabase появятся позже. Задача ЛР 2 и ЛР 3 — отработать навигацию, типизацию, формы и локальное состояние. `localStorage` в этой задаче не требуется и не добавлялся.

### 2. Где хранится общий список задач?
Общий список хранится в состоянии `App` через `useState`, и затем передаётся в дочерние страницы через props. Это важно, чтобы все страницы работали с одним и тем же массивом, а не с отдельной копией.

### 3. Почему не делается прямой мутация массива?
Потому что React не реагирует на изменения, если массив или объект изменены напрямую. В проекте используется паттерн immutable update: создаётся новый массив через `setTasks(current => ...)`, `map`, `filter` и `spread`.

### 4. Что происходит при отмене формы?
Форма редактирует собственный локальный черновик `draft`. Изменения в него вносятся во время ввода, а в общий список записи сохраняются только после успешной валидации и отправки формы. Поэтому отмена закрывает форму без сохранения.

### 5. Как обрабатывается ошибка ввода?
Ошибка показывается в одном месте через `role="alert"` и текстовое сообщение. Поля не сбрасываются, пользователь видит, что именно было заполнено неверно, и может исправить значение без потери введённых данных.

### 6. Почему в маршрутах есть `tasks/:id` и `tasks/:id/edit`?
Это стандартная структура для карточки задачи и её редактирования. Один маршрут отвечает за просмотр записи, второй — за форму изменения. Поскольку `:id` — динамическая часть URL, приложение может открыть нужную запись по прямой ссылке.

### 7. Что будет после обновления страницы?
Список восстанавливается из исходного демонстрационного набора, потому что данные хранятся только в памяти сеанса. Это соответствует заданию лабораторной: постоянное хранение появится позже вместе с Supabase.

### 8. Как проверялась корректность работы?
Проверялись следующие сценарии:
- открытие списка и карточек;
- создание новой задачи;
- редактирование и отмена редактирования;
- удаление с подтверждением;
- фильтр по статусам;
- проверка неизвестной задачи и неизвестного маршрута;
- успешная сборка проекта через `npm run build`.
